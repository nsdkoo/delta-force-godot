# 三角洲行动 · 胜者为王（Godot 2D）

俯视 2D 战术对战原型。玩法内核取自《三角洲行动 · 全面战场》的「胜者为王」模式：
**20 v 20 攻防 + 票选指挥官 + 战术标记 + 据点票数结算**。

不是一个单人射击游戏，重点在**指挥链驱动的小队 AI**。

```
Godot 4.7 · GDScript · 26 个脚本 / 5318 行 / 4 个场景 / 7 个 autoload
全程序化生成地图 · 零外部音频资源 · 运行期不依赖网络
```

# 一、架构

## 1.1 分层

```
┌─ autoload/ ────────────────────────────────────────────────┐
│  event_bus      事件总线    战斗侧只 emit，表现侧只 connect  │
│  game_config    数值表      枚举 / 世界常量 / 干员 / 武器   │
│  asset_db       资源加载    按 id 找，缺失退程序化绘制      │
│  match_state    战局状态机  票数 / 据点 / 区域 / 胜负        │
│  team_manager   战场名录    单位注册 + 空间查询 + 视线判定   │
│  audio_manager  音效       代码合成 + 2D 空间衰减            │
│  streak_manager 连杀奖励    门槛判定 + 支援释放 + 落弹调度   │
└────────────────────────────────────────────────────────────┘
                          ↓ 被引用
┌─ scripts/ ─────────────────────────────────────────────────┐
│  main            流程编排  ELECT → DEPLOY → FIGHT → RESULT  │
│  actors          Soldier · Vehicle · PlayerController       │
│  ai              BotBrain · VehicleBrain · Commander · Squad│
│  projectiles     Bullet · Missile · Grenade · Medkit        │
│  systems         JinqiuMap · BattleManager · CapturePoint   │
│                  · FxLayer（爆炸与弹着表现）· SelftestRunner │
│  ui              HUD（含战术地图与计分板，纯自绘）           │
└────────────────────────────────────────────────────────────┘
```

## 1.2 三条设计原则

**一、逻辑与表现分离。**
`Soldier` 不知道自己是人还是 AI，也不知道 UI 长什么样。
`PlayerController` 的唯一职责是把键鼠翻译成两个字段：

```gdscript
soldier.move_dir   # 世界空间移动方向
soldier.aim_point  # 瞄准点
```

换手柄、接观战、接回放都不用碰战斗逻辑。

**二、一切经 EventBus。**
战斗逻辑只 `emit`，UI / 音频 / 屏幕震动只 `connect`。
**没有任何一行 UI 代码直接引用战斗对象** —— 所以后期加击杀播报、受击红屏、连杀提示，全程不用改 AI 一个字符。

**三、三级指挥链，且 AI 与玩家同构。**

```
CommanderAI  ──set_order()──▶  Squad  ──apply_order()──▶  BotBrain
     ▲                                                        │
     └──────────── 玩家接管时只改 is_player 一个标志位 ────────┘
```

玩家当选指挥官后 `CommanderAI` 停用，改由玩家在战术地图下达 —— 但指令走的是**同一条** `Squad.set_order()` 链路。
**AI 指挥和玩家指挥对下层完全等价，不存在两套分叉分支。**

## 1.3 数据流

```
输入 ─▶ PlayerController ─┐
                          ├─▶ Soldier.move_dir / aim_point / want_fire
BotBrain ─────────────────┘
                                │
                                ▼
                         Soldier 执行
                     （移动 / 转向 / 射击 / 技能）
                                │
                                ▼
                        EventBus.emit(...)
        ┌───────────────┬───────────────┬──────────────┐
        ▼               ▼               ▼              ▼
    HUD 更新        音效播放        屏幕震动       MatchState 结算
                                                  （票数 / 据点）
```

`MatchState` 是唯一的「真相源」：票数、据点归属、占领进度、胜负判定全部集中在这里。
战斗单位只上报事件，不自己改战局数字。

# 二、关键实现

## 2.1 寻路

用引擎内置的 `AStarGrid2D`，不做手写 A*。理由：

- 自带**障碍膨胀**（agent 半径自动折算成格子数），不用自己处理贴墙
- 自带路径平滑，省掉后处理
- 网格地图天然支持「可通行格」预计算（本项目 60×41 网格 / 1393 个可通行格）

地图生成后一次性建图，运行期只做查询。AI 的重寻路间隔按 0.8~1.6 秒抖动，**各单位相位错开**，避免四十个人在同一帧集中开销。

## 2.2 视线与索敌

索敌不是简单算距离，是三重判定：

```gdscript
for e in enemies:
    if dist > view_range:            continue   # 1. 距离
    if fwd.dot(dir) < cos_half_fov:  continue   # 2. 视野锥（118° 全角）
    if blocked(eye, target_chest):   continue   # 3. 射线遮挡
```

**只做距离判定的话，AI 会隔着整片建筑群精准对射，看起来非常假。**

另外两条：
- **冲刺时视野收窄**（145m → 96m），让「跑步等于放弃观察」这件事有战术代价
- **索敌按 0.18~0.35 秒轮询**，不是每帧。四十个单位每帧打三条射线，帧率会直接崩

## 2.3 弹道

用 `PhysicsRayQueryParameters2D` 做**逐帧扫掠**，而不是让子弹当独立物理体飞：

- 高速子弹不会穿透目标（离散碰撞的经典问题）
- 一次射线查询比维护几十个物理体便宜得多
- 命中点、法线、命中部位（爆头判定）一次拿到

伤害随距离衰减：

```
dist ≤ falloff_start  → 满伤
dist ≥ falloff_end    → 45% 伤害
中间线性插值
```

## 2.4 据点占领

进度由**净人数差**驱动，不是「站上去就涨」：

```gdscript
if attackers > 0 and defenders == 0:
    progress -= dt * (100 / CAPTURE_TIME) * speed_for(attackers)
elif defenders > 0 and attackers == 0:
    progress += dt * (100 / CAPTURE_TIME) * speed_for(defenders)
else:
    contested = true   # 双方都在圈内 → 僵持，进度不动
```

`speed_for()` 是人多推得快但**收益递减**（`1.0 + min(2.0, (n-1) * 0.45)`），避免 20 个人挤一个点秒占。

这条比「占领进度条」更接近真实攻防：**要真正把人堆进去才能推下来**。

## 2.5 指挥链的指令语义

四条指令，每条都**硬性改变 AI 行为**，不是贴标签：

| 指令 | 对 AI 的实际影响 |
|---|---|
| **进攻** | 向目标据点推进，楔形展开保持间隔 |
| **防守** | 目标追出 `DEFEND_RADIUS`(46m) 就放弃回防；到位后原地警戒 |
| **前进** | 维持推进意愿 |
| **警示** | `AcquireTarget()` 直接 return，**完全不索敌** |

两个设计细节：

- **防守必须限半径**。没有这条，「防守」会退化成「无脑追人」，据点必丢
- **防守下发时按成员序号在半径上错开站位**。整队挤在一个坐标，2D 里会互相挡枪线

## 2.6 载具与 APS

载具拆成**车体 + 炮塔**两个独立朝向节点：车体走行进方向，炮塔独立锁敌，炮塔转速受限（形成「被绕侧就危险」的战术后果）。

**转速受限不是写个常量就完了。** 炮塔必须是「朝目标方向追」，而不是「直接把角度赋值成目标角度」——直接赋值的话，炮塔在任何一帧都能瞬移到任意方向，侧翼包抄就失去了意义。实现上单帧转角被 `TURRET_SLEW * delta` 夹住（约 150°/s），主炮只有在炮口与目标夹角小于 0.12 弧度时才允许击发。所以「被绕侧」是一个真实存在的战斗后果，而不是一句设计口号。

**玩家可以驾驶**（`F`）。上车后 `VehicleBrain` 让出控制权，键鼠交给 `PlayerController` 写同样的两个字段：

```
PlayerController ──move_dir / turret_dir / want_fire──▶ CombatVehicle
VehicleBrain     ──move_dir / turret_dir / want_fire──▶ CombatVehicle
```

AI 驾驶和玩家驾驶对载具完全等价，和步兵的 `Soldier` 一样不存在两套分支。操作：左键开炮（主炮 + 机枪）、`1/2` 切穿甲/高爆、`3` 开 APS、`F` 下车。

**乘员状态必须跟着车走。** 上车时乘员退出物理世界（碰撞层与掩码清 0），否则车上会留下一个看不见的碰撞体挡人挡枪；同时每帧同步 `global_position` 到车体，否则据点占领和敌方索敌都会按上车点算，出现「人在车上、却在原地占点」。载具被击毁时乘员会被抛出而不是凭空消失——抛出来的是一口气的重伤状态，不是满血逃生。

**APS 主动防御**是入场券：6 秒拦截窗口 / 32 秒冷却。开着 APS 才能顶着反载火力推进，工程兵的巡飞弹要挑它冷却的空档打。

## 2.7 连杀奖励

3 / 5 / 8 / 12 连杀四档，阵亡清零。

| 门槛 | 奖励 | 释放方式 |
|---|---|---|
| 3 | 无人机侦察 | 即时生效，敌方位置暴露 10s |
| 5 | 迫击炮支援 | 按 `X` 在瞄准点落地 8 发 |
| 8 | 空中打击 | 按 `X` 沿瞄准方向拉一条 12 发弹幕线 |
| 12 | 载具增援 | 按 `X` 空投一辆己方装甲车 |

两个设计上的取舍：

**支援击杀不计入连杀。** 否则会自举：5 杀拿迫击炮，迫击炮炸死 3 个直接跳到 8 杀拿空袭，空袭再炸出 12 杀——一局只要开一次头，后面全靠支援自己喂自己。规则上只认玩家亲手打出来的击杀。

**弹幕的散布和杀伤半径是配套调的。** 迫击炮一开始写成散布 ±210 / 杀伤 100，理论上单发对某个具体目标的覆盖概率只有约 18%，8 发下来大概率一个都炸不死——那不叫支援，叫放烟花。收窄到 ±120 并让杀伤半径略大于散布步长，才有「覆盖」的意思；空袭的弹着间距 128 小于杀伤半径 140，相邻炸点必须重叠，否则地面会漏出一条走位通道让人从缝里走过去。

## 2.8 特效

`EventBus.explosion` / `EventBus.impact` 这两个信号从一开始就在发，但一直没有监听方。`FxLayer` 把它们接上：炮口焰、爆炸火球、火星、烟柱、弹着扬尘。

实现上没有「每次爆炸 new 一个 Sprite2D」，而是把特效压成一条纯数据记录，统一在一个节点的 `_draw` 里画完。四十个单位交火时每秒会产生上百个弹着点，逐事件建节点会让场景树在几秒内肿胀到几千个对象，随之而来的定位与释放开销比绘制本身还大。节点数恒定为 1，也没有对象池要维护。

辉光走 HDR：颜色分量给到 1.0 以上（如 2.4），引擎的 HDR 2D + Glow 会把超亮部分晕开，不需要混合模式（Godot 4 已移除 `draw_set_blend_mode`），也不额外引入 ShaderMaterial。

## 2.9 音效合成

**21 条音效全部代码合成，零音频资源文件。**

做法是「噪声 + 包络 + 一阶低通」：

```gdscript
# 枪声：极快攻击段 + 指数衰减噪声尾
env = exp(-t / body)              # body 越大尾音越长
prev += alpha * (noise - prev)    # 一阶低通，alpha 越小声越闷
v = prev * env + prev * exp(-t * 0.8 / tail) * 0.35
```

按口径分档：冲锋枪短促、突击步枪中等、机枪低沉、狙击枪爆裂、火箭筒带长尾。
再加一条 `shot_far`（更闷更长）给远处的枪声。

好处不只是省体积 —— **同一把枪的射速、口径、室内外都能靠参数区分**，不必准备十几个采样。
3D 空间感靠 `AudioStreamPlayer2D` 的距离衰减与声像。

# 三、渲染

## 3.1 2D 光照

**Godot 的 2D 光照是做出来的，不是叠一层暗色。**

```
WorldEnvironment(HDR 2D + Glow + ACES)
  ├─ CanvasModulate      环境天光（乘性）
  ├─ DirectionalLight2D  太阳：低角度 −37°，投长阴影
  └─ LightOccluder2D     建筑遮挡体
```

两个关键设置：

**light mask 分层** —— 地面 = `0b0001`，单位 = `0b0010`。
建筑给地面和单位投阴影，但**建筑自己退出光照链路**（`light_mask = 0`），否则它会被自己压成一个黑洞。

**CanvasModulate 压在 bloom 之后** —— 这样能压暗画面但**保留辉光**，枪口焰和爆炸的亮部不会被压掉。

## 3.2 地表烘焙

地表**不是一张平铺贴图**，是离线烘焙的分层产物（`_bake_terrain.py`）。

流程：

```
Godot 导出地图数据 (_map_dump.json)
        ↓
Python 读取建筑 / 道路 / 据点坐标
        ↓
从 ambientCG 拉 CC0 PBR 材质，按真实尺度多层混合
        ↓
同时烘焙配对的法线图 → 让低角度太阳在地面打出凹凸
        ↓
输出 assets/terrain/ground_color.jpg + ground_normal.jpg
```

**尺度**是关键：一张 1024 贴图铺满 3000 米战场，每像素代表 3 米，细节全被拉平。
必须按真实物理尺度平铺（`wrapMode = Repeat` + `anisoLevel`），否则地表永远是糊的。

## 3.3 建筑伪立体

建筑用**手绘三面**（顶面 / 南墙 / 东墙）+ 高度偏移模拟立体感，不用 3D。

```
顶面 = 屋顶色
南墙 = 顶面 * 0.78（受光面）
东墙 = 顶面 * 0.62（背光面）
整体向上偏移 off = h * 23 * 0.44
```

配合 `LightOccluder2D` 投出的真实阴影，画面就有体积了。

# 四、性能

四十个单位 + 载具 + 投射物，核显上要稳 60 帧，主要靠三条：

**一、查询集中化。**
`TeamManager` 统一持有单位列表。AI 问「最近的敌人」「这个点周围几个自己人」走一次遍历。
如果让每个 AI 自己遍历场景树，40 个单位就是 40 次全树遍历。

**二、轮询抖动。**
索敌（0.18~0.35s）、重寻路（0.8~1.6s）都不是每帧做，且**各单位起始相位随机错开**，避免同一帧集中开销。

**三、分层碰撞。**
`world` / `gti` / `havoc` / `projectile` / `hitbox` / `pickup` / `vehicle` 七层。
`collision_mask` 精确控制谁能撞谁 —— 子弹不会和子弹碰撞，同队不会互相阻挡射线。

# 五、玩法概览

| 系统 | 实现 |
|---|---|
| 兵力 | 20 v 20。GTI（进攻）vs 哈夫克（防守） |
| 票数 | 320 : 260。阵亡扣 1 票；**占点攻方 +15 / 守方 −10**；区域突破 +80 |
| 据点 | 6 个，A / B / C 三段递进，未解锁区域的据点强制归守方 |
| 指挥官 | 3 名 AI 候选 + 玩家可自荐，得票最高当选 |
| 干员 | 红狼（突击）· 蜂医（支援）· 乌鲁鲁（工程）· 露娜（侦察） |

| 计分板 | 按住 `Tab` 展开双方 20 人 + 装甲，按得分排序 |

**地图「烬区」**按真实结构程序化生成：

```
西侧外围荒地（攻方高地）
  → A 岩下村（低洼村落，村墙环绕，留多个通道口）
  → B 临时营地（中心独立建筑 + 沙土围墙）/ 贫民窟（连片房屋）
  → 中央市政大楼（地标高塔）
  → C 军需仓库（大型仓库 + 双层围墙）/ 办公区
  → 东侧守方基地
```

实测规模：**94 栋建筑 / 74 处地物 / 74 个遮挡体 / 60×41 导航网格 / 1393 可通行格**。

# 六、运行

用 **Godot 4.7+** 打开本目录，按 **F5**。首次导入素材约十几秒。

```bash
# 首次（或新增 class_name 后）需要导入注册
Godot.exe --headless --path . --import

# 正常运行
Godot.exe --path .

# 无头自动验证：跳过交互直接开打，周期性输出战局快照
Godot.exe --headless --path . --quit-after 2500 -- --auto

# 无头逐条自检：断言载具链路 / 连杀奖励 / 炮塔限速 / 乘员安全，失败返回退出码 1
Godot.exe --headless --path . -- --selftest

# 截图（读 viewport 纹理，不受窗口遮挡影响）；配合 --demo 出定型画面、--scoreboard 展开计分板
Godot.exe --path . --resolution 1600x900 -- --demo --shot=6
Godot.exe --path . --resolution 1600x900 -- --demo --scoreboard --shot=6
```

# 十、开发备注

踩过的坑，留个记录：

- **2D 俯视画人形角色天生吃亏** —— 一个士兵在纯俯视图里就是圆点加一根枪管。这是视角的物理限制，换素材解决不了
- **地表贴图不平铺等于白做** —— 见 3.2
- **围墙别四面围死** —— 会直接把 AI 关在里面出不来
- **`EventBus.Clear()` 不能放在重开局里** —— 会把 HUD 已建立的订阅一起清掉，重开一局界面就不再更新。清理要放到场景 `_exit_tree()`
- **中文必须用 `SystemFont`** —— Godot 内置字体不含 CJK，直接用会显示成方块
- **`Vector2i` 是值类型，「传进去改」是空操作** —— 导航原来写的是 `_clamp_cell(a)`，函数内部改的是形参的副本，调用方的 `a` 一点没变。越界坐标一路带进 `AStarGrid2D`，AI 走到地图边缘就刷 `out of bounds`。改成返回新值再赋值
- **`setup()` 必须在 `add_child()` 之前调用** —— 节点的 `_ready` 在入树时就跑。载具的 `_ready` 按 `kind` 取数值表和贴图，顺序反了的话两种车都会拿到默认的坦克数据，APC 在战场上根本不存在
- **载具被摧毁不能只把 `driver` 置空** —— 那样乘员会以「隐形 + 零碰撞」的状态留在原地。必须是：抛出 → 恢复碰撞与可见 → 按重伤处理
- **乘员的 `global_position` 要每帧同步到车体** —— 据点占领、索敌、AI 选目标全部按坐标算半径。人在车上而坐标停在上车点，就会出现「原地占点」和「敌人朝空地开枪」
- **下车后要立刻 `return`** —— `_release_vehicle()` 会把 `vehicle` 置空，继续往下走会在同一帧里解引用空对象
- **容器会吃掉绝对定位** —— 面板一开始用 `PanelContainer`，它是容器，布局时会把每个直接子节点都 fit 进自己的内容矩形，于是 `label.position = Vector2(30, 30)` 这类写法全部作废，选举面板里标题、候选人列表、参选按钮被压到同一处。要"一个边框底 + 绝对定位的子节点"，用 `Panel` 而不是 `PanelContainer`
- **自检里的玩家要开免伤** —— 断言之间有十几秒的等待，敌方 AI 完全可能把玩家打死，一死连杀清零，后面每一档的断言全部错位。同理，用作靶子的机器人会自己走开，散布型火力的杀伤断言不能指望「一定炸死几个」
