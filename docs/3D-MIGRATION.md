# 3D 迁移方案（决策记录）

> 2026-09-18 · 起因：教练看了同类游戏的实机截图，认为现在的 2D 画面"太简单"，
> 要求去找开源项目对照，考虑直接在别人的 3D 项目上改。

## 一、为什么会显得简单（有数据的诊断）

拿三个参考工程和本项目对比（用 `refs/analyze_project.py` 统计）：

| | godot-open-rts | TowDownGame | **本项目** |
|---|---|---|---|
| GDScript | 118 文件 / 7297 行 | 105 文件 / 5469 行 | **30 文件 / 7867 行** |
| 平均每文件 | 62 行 | 52 行 | **262 行** |
| `.tscn` 场景 | **84** | **102** | **4** |
| `.tres` 资源 | 8（含材质/主题） | 6（含 UI 主题） | **0** |
| 本地化 | csv ×2 | csv ×1 | 无 |

结论不是"功能少"，是**工程形态不同**：

1. **没有内容层**。人家 84~102 个场景，每个 UI 组件、每种子弹、每把枪都是编辑出来的
   独立资产；我这里 4 个场景，界面全靠 `_draw` 和代码 `new()` 拼出来。
   后果：改一个 UI 组件要动 736 行的 hud.gd，美术没法并行插手。
2. **没有配置层**。人家把材质、主题、翻译都做成资源文件；我所有数值都是 GDScript
   里的 `const` 字典，改平衡 = 改代码 = 重跑自检。
3. **单体脚本**。`jinqiu_map.gd` 914 行（地图+建筑+地物+地形+碰撞+导航），
   `hud.gd` 736 行。职责没有边界。
4. **渲染维度**。上面三条是工程问题，这一条是观感问题：2D 没有真实投影、
   没有体积、没有空气透视，再怎么调色也到不了"低模 + 光影氛围"那个档位。

## 二、已经验证过的东西

- **3D 观感可以复现**：`refs/probe3d/` 用纯程序几何（圆锥树 + 胶囊小人）搭了一个
  等距视角场景，配天空散射环境光 + 斜射平行光 + 距离雾 + SSAO/SSIL + ACES。
  模型糙，但光影关系已经成立 —— 说明差距主要在**资产**和**维度**，不在美术功底。
- **开源底座找到了**：`refs/ex/godot-open-rts-main/`（MIT 代码 + Kenney CC0 素材），
  Godot 4.3 兼容，自带等距相机 / 单位选择 / 小地图 / 战争迷雾 / 导航 / VFX /
  主菜单外壳 / csv 本地化。实机截图确认了它的菜单就是"3D 场景 + 菜单"的形态。
- **素材源**：Kenney **Nature Kit**（330+ 低模自然物件，CC0，10MB）已下载校验完毕
  （3626 条目，zip 完整）。这类 CC0 包是风格统一的主力。
- **开源项目的下载姿势**：GitHub 直连 codeload 会被截断（稳定断在 695721 字节），
  `git clone` 报 invalid index-pack，api.github.com 直接连不上。
  **走 `https://gh-proxy.com/` 前缀代理 codeload 链接能拿到完整包** —— 这条要记住。

## 三、结论：改，但不是推倒重来

**规则与数据层原样搬过去，表现与实体层重写。**

可以直接搬（和维度无关）：
`GameConfig` 的数值表、`MatchState`（兵力/加时/据点归属）、`CommandOps`（阵营积分、
指挥官技能、重火力、工事额度、弹劾）、`StreakManager`（连杀与支援落弹调度）、
四维能力标签的口径、`CREDITS.md`。

需要重写（2D 专属）：
`jinqiu_map.gd`（→ 3D 地形 + NavigationRegion3D）、`soldier.gd` / `vehicle.gd`
（→ CharacterBody3D + NavigationAgent3D）、`bullet.gd`（→ 射线 3D）、
`hud.gd`（→ Control 场景树 + 3D 小地图）、`fx_layer.gd`（→ GPUParticles3D）。

## 四、目标工程结构（照 open-rts 的分层抄）

```
delta-3d/
  autoload/          MatchSignals(事件总线) / DataService(读 data/) / ProgressService
  data/              *.json  干员/武器/载具/工事/技能/地图 —— 配置出代码
  source/
    main-menu/       主菜单 / 设置 / 读档（每个页面一个 .tscn）
    match/           Match.gd 只做装配与胜负判定
      maps/          地图数据 + 地形装配
      units/         Unit.gd + traits/（移动/开火/倒地 各一个组件场景）
      handlers/      输入、选择、部署、建造
      hud/           血条 / 小地图 / 指挥官面板 / 计分板
      fx/            GPUParticles3D 特效
  assets/            kenney/  nature-kit、characters、vehicles（CC0）
  assets/translations/  zh.csv / en.csv
```

硬规矩（从这次 2D 项目学到的，别再犯）：
- 单文件不超过 250 行；超了就拆 trait / handler
- 界面一律 `.tscn`，不再用代码 `new()` 拼 —— 这是"没法并行迭代"的根
- 数值一律进 `data/*.json`，代码里只留结构

## 五、Tripo3D 这类 AI 生成器的定位

查证结论（2026-09 检索）：文生/图生 3D，输出 GLB/FBX/OBJ/USD，有 Godot 插件和
REST API；免费档 200~300 积分（约 8~12 个模型/月）但**非商用且模型公开**，
商用要 Pro（$19.9/月）。第三方评测的一致结论：**道具/环境/批量出块很好用，
十成里大概只有一成不用修就能直接进项目**；文字直出 3D 不适合生产；
角色要做动画必须重新拓扑。

放到本项目里的定位：
- **能用**：补 CC0 包没有的独特道具（哨塔、掩体变体、 mission 专属地标），
  以及给某个想法快速出个占位模型看比例 —— 这正是它最强的"十分钟出块"场景
- **不能当主力**：几百个资产要风格统一，AI 逐个生成的风格漂移会毁掉整体观感；
  角色的拓扑/绑定为生产级动画不可用
- **授权红线**：免费档生成的模型不可商用，真要用必须上 Pro ——
  这个项目目前是个人练习，可以先在免费档试质量，等要发布再决定

结论：**主力 = Kenney/Quaternius 等 CC0 现成低模包；Tripo 只做补缺和快速占位。**

## 七、probe3d 跑通之后记下的坑（2026-09-18）

`refs/probe3d/` 已经从"程序几何占位"推进到"Kenney Nature Kit 真模型"（308 棵树、
30 种模型、营地建筑群）。这一路踩到四个必须记下来的坑：

1. **Kenney 的 GLB 进 Godot 会整体偏色**：树冠变青、石头变粉。
   原因是它的模型用共享调色板贴图 + 顶点色，Godot 的 GLTF 导入把色彩空间
   转换跑偏了。解法是按"冷暖色调"判断面归属，把 albedo 强制拉回期望主色，
   **并且必须把 albedo_texture 清空** —— 不清的话颜色会被贴图再乘一遍，等于没改。
   `_normalize_colors()` 就是干这个的。
2. **不要给同一批模型做颜色抖动**：先 duplicate 材质再改 albedo_color，
   会让调色板映射彻底坏掉。想要差异应该混用不同款模型（这个包一棵树就有
   9 个变体），而不是动材质。
3. **地形压平中心的径向衰减会留下规则的圆形等高线**，远看像指纹图案。
   解法是压平改用 smoothstep，再叠一层高频噪声把圆形轮廓打碎。
4. **顶点色按高度染色在缓坡上会出现一圈圈色带**（摩尔纹），
   低模就该平涂 + 光影，别在顶点色上做渐变。

另外：验证不要开窗口 —— 教练在打真游戏，任何带界面的进程都会把他切出对局。
一律 `--headless`，截图单独找时间补。
